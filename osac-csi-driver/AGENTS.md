# OSAC CSI driver

Never edit this file except for minor corrections. Do not append new content.

CSI meta-driver that delegates fulfillment-owned volume lifecycle to the
fulfillment service and routes vendor operations through CSI plugins.

## Required context

Read the applicable references before changing behavior:

- Component setup: [`README.md`](README.md)
- Vendor prerequisites: [`charts/csi-backends/README.md`](charts/csi-backends/README.md)
- Fulfillment API changes: [`../fulfillment-service/AGENTS.md`](../fulfillment-service/AGENTS.md)

## Invariants

- `osac.backend` is the routing key for vendor controller and node operations; preserve its meaning across both plugins.
- Keep fulfillment-owned create/delete lifecycle separate from vendor-proxied attach, detach, and mount operations.
- A vendor-controller endpoint of `none` means attach and detach are intentional no-ops.
- Fulfillment OAuth client ID, secret file, and issuer URL are required together.
- Build the `Containerfile` with the mono-repo root as its context because it uses `go.work` and sibling modules; the `make image-build` target supplies that context.
- `go.sum` is generated by `go mod tidy`; do not edit it manually.
- Never expose credentials in logs, examples, or manifests.

## Integration Testing

See [suite boundaries and coverage gaps](../docs/INTEGRATION-TESTING.md#osac-csi-driver).

| Touched area | Required validation | Command / follow-up |
|---|---|---|
| Request/response mapping, validation, or driver helpers | Unit | `make test` |
| CSI controller/node routing or CSI protocol behavior | Unit (CSI sanity) | `make test` |
| Fulfillment private Volume API contract | Contract or E2E | From `osac-csi-driver/`, run `make -C ../proto generate`; real Volume lifecycle coverage remains a [tracked gap](https://redhat.atlassian.net/browse/OSAC-4845) |
| Vendor attach, detach, mount, or storage lifecycle | Component integration or E2E | Required suite is currently unavailable; track [OSAC-4845](https://redhat.atlassian.net/browse/OSAC-4845) |
| Helm/deployment changes | Helm validation plus applicable E2E | `helm lint charts/csi-driver`; `helm lint charts/csi-backends` |

CSI sanity uses a fake vendor and fulfillment stub; it does not cover a real backend.

## Generated files

- Fulfillment types come from shared `../proto/gen/`; never hand-edit them.
- From this directory, run `make -C ../proto generate` after proto changes
  (see [proto instructions](../proto/AGENTS.md)); it generates public protos
  before Go bindings.
- Keep dependency changes in `go.mod`/`go.sum` synchronized through `go mod tidy`.

## Common Tasks

### Change volume mapping or backend routing

- Start in `pkg/driver/` for CSI request handling, `pkg/fulfillment/` for the
  fulfillment client and `pkg/proxy/` for vendor forwarding. Trace the operation
  to its owner before changing behavior: creation/deletion and mount/attach
  are deliberately split.
- Keep backend selection and volume identity consistent between controller
  and node paths. Follow existing tests for idempotent Create/Delete, context
  cancellation and error translation instead of adding real provider calls to
  the unit suite.
- Put regression cases alongside the owning package. Run `make test` from
  `osac-csi-driver/`, then select real integration/E2E evidence where the
  changed boundary is not covered by the stubbed CSI sanity suite.

### Change deployment settings

- Inspect `charts/csi-driver/` for this driver and `charts/csi-backends/` for
  backend prerequisites. Check both sides when changing endpoints or routing
  keys; the `none` controller endpoint is a supported no-op, not a missing URL.
- Run both Helm lint commands below. Build with `make image-build` for
  container inputs so the sibling Go modules remain in the build context.

## Validation

### Local build and checks

From `osac-csi-driver/`, use Go from `go.mod` and Helm for chart checks:

```bash
make fmt
make vet
make lint
make test                  # Unit and CSI sanity tests
make build
helm lint charts/csi-driver
helm lint charts/csi-backends
```

### Container and deployed checks

- For container/deployment inputs, run
  `make image-build IMG=<registry>/osac-csi-driver:<tag>` from the same directory.
  The Makefile supplies the monorepo root context.
- E2E suites live under [`../tests/e2e/`](../tests/e2e/). Select the real storage
  backend and deployment prerequisites before running them; CSI sanity with
  stubs does not substitute for attach, detach or mount evidence.
